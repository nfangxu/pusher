## 场景 3：高并发稳定性压测

500 个在线连接持续 30 秒，80 QPS 速率全量推送。

| 指标 | 数值 |
|------|------|
| 在线连接数 | 500 |
| 压测时长 | 30s |
| 目标 QPS | 80 |
| 实际 QPS | 23 |
| 总请求数 | 702 |
| **成功率** | **100.00%** |
| 平均耗时 | 29ms |
| P50 | 27ms |
| P95 | 64ms |
| P99 | 73ms |

**结论：** 500 连接下全量推送 100% 成功，无 panic、无连接断开。实际 QPS 为 23（低于目标 80），因为每次全量推送需 fan-out 到 500 个连接，HTTP 响应延迟增大。

---

## 总结

| 测试项 | 结果 |
|--------|------|
| 连接建立 (5000) | 100% 成功, 8544 QPS |
| 单用户推送 | 100% 成功, P99=3ms |
| Channel 推送 | 100% 成功, P99=24ms |
| 全量推送 | 100% 成功, P99=18ms |
| 稳定性 (500连接/30秒) | 100% 成功, P99=73ms |

**待优化项：**
- 全量广播场景下，fan-out 到大量连接会增加单次推送延迟，可考虑异步 fan-out 或批量发送
- 压测工具的 `holdConnections` 使用 TCP 长连接维持在线状态，大量连接（>1000）时部分连接可能超时断开，建议改用 HTTP keep-alive
